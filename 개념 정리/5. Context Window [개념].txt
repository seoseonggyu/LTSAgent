Context Window
- LLM은 기억을 못한다.
- 왜 기억을 못할까? LLM은 상태를 유지하지 않는 시스템이다.
- 매 API 요청은 완전히 독립적이다. 서버에 이전 대화를 저장하지 않는다.
- 대화가 이어지는 것은 착각이다. 매번 이전 대화를 통째로 다시 보내주는 것이다. LLM은 매번 처음부터 다시 읽는 것이다. 이게 바로 Context Window 다.

Context Window
- LLM이 한 번에 처리할 수 있는 토큰의 최대 크기
- 비유로는 Context Window는 상담사의 책상 크기다. 한 번에 올려놓고 볼 수 있는 메모지의 양에 한계가 존재한다. 모델마다 책상 크기가 다르다.
- 참고로 1토큰은 한국어 한 글자 ~ 반 단어 정도다 (영어는 약 3/4 단어)


한계가 존재하는 이유
- LLM이 내부적으로 토큰을 파싱할 때, 토큰이 2배가 늘어나면 연산량은 제곱으로 늘어나기 때문이다. 그래서 각 토큰을 처리하는 GPU 메모리가 물리적으로 한계가 있기 때문에 한계가 존재한다. 컨텍스트 윈도우의 한계는 단순히 "아직 못 늘린 것"이 아니라 연산, 메모리, 비용, 품질 모두와 연결된 근본적인 제약이다. 추가적으로 컨텍스트가 길어지면 LLM은 어쩔 수 없이 처음과 마지막은 잘 보는데 중간은 좀 놓친다.


책상이 꽉 차면?
- 메모리가 너무 많아서 책상 위에 다 올려놓을 수 없다. 오래된 메모리를 치우거나, 요약해서 자리를 만들어야 한다. 잘라내기(오래된 메시지 버림), 요약하기(이전 대화를 짧게 요약해 압축) 2가지 방법이 있다.


잘라내기
- 잘려나간 초반 대화 내용을 모델이 알 수가 없다.

요약하기
- 적은 토큰으로 맥락이 유지가 되지만 요약 과정에서 세부사항 손실 가능
- 이 요약을 잘 만드는 것이 바로 Agent의 역할이다.
- ChatGPT, Claude 같은 서비스는 자체적으로 요약을 알아서 해준다.

요약이 중요한 이유
- 효율적인 Agent 설계: 컨텍스트 윈도우를 잘 관리하는 것이 Agent 설계의 핵심 과제
- 비용 최적화: 불필요한 토큰을 줄이면 API 비용을 크게 절약
- 사용자 경험: 맥락을 잘 유지해야 자연스러운 대화 경험을 제공
