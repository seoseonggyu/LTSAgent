Web Search 도구
- 필요한 이유는 LLM은 학습 시점까지의 지식만 갖고 있다. "오늘 날씨", "최신 뉴스" 같은 실시간 정보에는 대답 불가. 웹 검색 도구를 달아주면 Agent가 인터넷에서 최신 정보를 가져올 수 있음.

weab_search가 하는 일 vs 하지 않는 일
- 하는 일: 키워드로 검색 엔진에 질의, 결과 리스트 반환(제목, URL, 게시일)
- 하지 않는 일: 페이지에 들어가서 본문을 읽지 않음, 본문 읽기는 web_fetch 라는 별도 도구가 필요
- 비유: 구글에서 검색해서 결과 목록만 보는 것

핵심 구조: 서브 API 호출 패턴
- 도구 내부에서 또 다른 AI를 호출하는 패턴
- 메인 AI(Sonnet / Opus) -> web_search(도구 함수) -> Haiku(서브 AI + 내장 검색)
- 메인 AI가 "검색해줘"라고 요청하면, 도구가 가벼운 모델(Haiku) 에게 Antrhropic 내장 웹 검색을 붙여서 서브 호출. Haiku가 실제 검색을 수행하고, 결과만 추출해서 메인 AI에게 돌려줌


왜 이렇게 설계했는가?
- 왜 직접 검색 API를 안쓸까? Anthropic이 제공하는 내장 웹 검색 도구를 활용하는 방식이라 별도 API 키 발급이나 복잡한 설정 없이 간편하게 구현이 가능
- 왜 메인 모델 대신 Haiku를 쓸까? 검색은 단순한 작업. 비싼 고성능 모델이 필요 없다.
- 왜 결과만 추출? 서브 AI의 전체 응답에는 불필요한 정보가 포함될 수 있다. 제목, URL, 게시일만 깔끔하게 추출해서 메인 AI에게 넘기면 토큰을 절약하고 정확한 판단이 가능하다.

설계 시 고려할 점
- 현재 날짜 주입. 서브 AI에게 오늘 날짜를 시스템 프롬프트로 알려줘야 한다. 그래야 "2025년 최신"과 같은 시간 기반 검색이 정확하게 동작한다.
