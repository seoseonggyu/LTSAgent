UNREALAGENT.md
- Agent의 프로젝트 별 지침 파일

핵심 비유 - 회사로 이해하자
- 시스템 프롬프트: 회사 전체의 공통 규칙 -> 모든 부서, 모든 프로젝트에 적용
- 지침 파일: 특정 프로젝트의 업무 메뉴얼 -> 이 프로젝트에서만 적용

지침 파일이 필요한 이유
- 시스템 프롬프트만으로는 부족한 상황
- 프로젝트마다 다른 기술 스택
- 프로젝트마다 다른 코딩 컨벤션
- 프로젝트마다 다른 폴더 구조
- 프로젝트마다 다른 금지 사항
- 이런 부분들을 매번 사용자가 직접 설명? -> 비효율적
- 파일로 만들어놓으면 Agent가 알아서 읽고 따름

지침 파일이란
- 프로젝트 루트에 놓는 마크다운(.md) 파일
- Agent가 시작할 때 이 파일을 읽어서 시스템 프롬프트에 합침
- Claude Code에서는 CLAUDE.MD

시스템 프롬프트 vs 지침 파일
- 역할:	Agent의 기본 성격	vs 프로젝트별 맥락과 규칙
- 적용 범위:	모든 프로젝트에 공통    vs	특정 프로젝트에만 적용
- 수정 권한:	개발자가 코드에 고정    vs	사용자가 자유롭게 수정
- 위치:	코드 내부      vs	프로젝트 루트(.md 파일)
- 비유:	회사 사규	     vs      프로젝트 업무 매뉴얼
- 둘 다 결국 Claude에게 합쳐져서 하나의 컨텍스트로 전달됨

지침 파일의 장점
- 매번 설명 불필요: 프로젝트 맥락을 파일이 대신 전달
- 팀 표준화: 누가 써도 같은 규칙이 적용
- 버전 관리 가능: Git으로 변경 이력 추적
- 즉시 반영: 수정하면 다음 대화부터 적용

트레이드 오프: 컨텍스트 윈도우
- 지침 파일이 너무 길면 대화에 쓸 공간이 줄어듦, 오래된 내용을 잘라내야 함
- 즉, 지침 파일을 너무 크게 하면 안된다

잘 쓰는 팁
- 명확하고 구체적으로 -> "좋은 코드를 작성" (X), "변수명은 camelCase, 함수는 동사로 시작" (O)
- 예시를 포함하면 효과적
- 프로젝트 진행에 따라 계속 업데이트
