Blazor에서 Agent를 안정적으로 운영하기 위한 구조 설계

근본 문제: Blazor의 UI 스레드
- Blazor Server는 SignalR 연결을 통해 서버에서 UI를 관리
- 이 연결은 단일 동기화 컨텍스트를 가짐 -> 한 번에 하나의 작업만 UI를 업데이트
- 화면에 뭐가 보이는지 변경할 수 있는 건 오직 UI 스레드뿐

Agent를 직접 호출하면?
- Agent API 호출은 수 초~수십 초 걸리는 무거운 작업
- UI 스레드에서 직접 하면 UI 갱신이 멈춘다.
- 스트리밍 글자가 나와야 하는데 화면이 얼어버림
- 스크롤, 버튼 클릭 등 사용자 조작이 먹통

여러 소스가 동시에 Agent를 호출하면?
- 사용자 send, 다른 Agent, 시스템 이벤트 -> AgentLool(하나뿐)
- 데이터 충돌 (같은 상태를 동시에 변경)
- 렌더링 오류 (UI 스레드 밖에서 상태 변경)

핵심 원칙
- "무거운 일은 백그라운드 스레드에서 하고, UI 업데이트만 UI 스레드로 던진다"


해결책: AgentRunner
- UI와 Agent 사이에 중간 관리자를 둔다
- 생산자 <-> 소비자 패턴
- UI는 큐에 넣기만 하고 바로 돌아감
- AgentRunner가 백그라운드에서 Agent를 실행
- 결과 이벤트를 UI 스레드로 Dispatch
