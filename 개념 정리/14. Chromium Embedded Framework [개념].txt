웹으로 만든 Agent 채팅 화면을, 언리얼 에디터 안에 하나의 탭으로 넣는 구조를 알아보자.

왜 웹 UI를 언리얼 에디터에 넣는가?
- 웹과 언리얼 에디터를 왔다 갔다 하는 게 귀찮아서 에디터 탭으로 통합

Chromium Embedded Framework (CEF)
- Chrome 브라우저의 핵심 렌더링 엔진(Chromium)을 다른 앱에 내장할 수 있게 만든 프레임워크
- Chrome 브라우저 -> CEF -> 내 앱

SWebBrowser - 언리얼의 CEF 래퍼
- 언리얼 엔진이 CEF를 감싸서 만든 Slate 위젯
- URL을 지정하면 해당 웹 페이지를 위젯 안에 표시
- 일반 언리얼 위젯처럼 크기 조절, 배치, 도킹이 가능

SDockTab - 에디터 탭으로 등록
- 언리얼 에디터의 탭 시스탬 (디테일, 월드 아웃라이너, 콘텐츠 브라우저 등)
- SWebBrowser를 SDockTab에 넣으면 -> 도킹, 이동, 탭 전환 모두 가능
- 사용자 입장에서는 에디터 기본 기능처럼 자연스럽게 느껴짐

연동 흐름 6단계
1. Blazor 웹 앱이 local에서 실행
2. 언리얼 플러그인이 SDockTab 생성
3. SDockTab 안에 SWebBrowser 위젯 삽입
4. SWebBrowser에 local URL 로드
5. CEF가 렌더링 -> 채팅 화면 표시
6. Agent와 대화 -> 실시간 응답

전체 파이프라인 - 요청부터 응답까지
- 에디터 안에서 웹 앱 -> 백엔드 -> AI까지 이어지는 전체 흐름
- 사용자 입력 -> SWebBrowser -> Blazor Fronted -> SignalR -> Backend -> Claude API
