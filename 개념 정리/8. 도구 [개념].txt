도구
- LLM은 Tool을 직접 실행하지 않고 Agent에게 요청한다.

참모와 부관 비유
- AI(LLM) = 참모 = 판단은 하지만 직접 행동 못함
- Agent = 부관 = 참모의 명령을 받아 실제로 실행
- Tool = 도구 = 부관이 사용하는 구체적 장비들
- ex) AI: "날씨 검색해줘" -> Agent가 실행 -> 결과를 AI에게 보고

도구
- AI가 외부 세계와 상호작용할 수 있게 해주는 기능 단위. AI 스스로는 텍스트만 생성할 수 있지만, Tool을 통해 실제 행동이 가능
- ex) 웹 검색, DB 조회, 계산기 등등


AI는 Tool을 어떻게 이해하는가?
- API 요청 시 Tool 목록을 JSON으로 정의해서 전달
- 3가지 핵심 요소
- 첫 번째 name(도구의 고유 이름): AI가 호출할 때 사용하는 식별자
- 두 번째 description(도구 설명): AI가 이걸 읽고 언제 쓸지 판단
- 세 번째 input_schema(파라미터 정의): JSON Schema로 인자의 이름, 타입, 설명
- description을 얼마나 잘 쓰느냐가 AI의 Tool 선택 정확도에 직접 영항

주의
- Tool도 컨텍스트 윈도우에 들어가기 때문에 자세하면 좋지만 필요 없는 정보까지 넣으면 문제가 생긴다.
- 도구를 3, 40개씩 만들면 안된다. 도구를 많이 만들면 컨텍스트 굉장히 커지기 때문이다.
- 어떠한 도구 하나를 만들 때 범용적으로 만드는 게 중요하다.
- ex) 도시의 현재 날씨를 조회합니다 -> 인터넷 검색(변경)

핵심 정리
- AI는 Tool을 직접 실행하지 않는다 -> Agent에게 "이 도구를 이 파라미터로 써달라"고 요청할 뿐
- Tool Definition이 곧 AI의 이해력 -> description을 잘 써 야 AI가 올바른 Tool을 선택한다
- Tool 결과는 반드시 role: "user"로 전달 -> AI 입장에서 외부 정보는 "상대방(에이전트)이 알려준 것"이기 때문이다
- stop_reason이 루프의 핵심 -> "tool_use"면 계속, "end_turn"이면 종료
- Agent는 단순한 while 루프일 뿐 -> 판단은 AI가, 실행은 Agent가, 도구는 Tool이 담당한다.
