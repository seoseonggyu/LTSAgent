언리얼 에디터를 AI로 제어하려면?
- 언리얼 에디터는 수백 가지 기능이 있다.
- 액터 배치, 레벨 관리, 지형 편집, 카메라 설정, 라이팅 설정.....
- 이 모든 걸 AI가 제어하게 하려면 각 기능마다 도구를 1대1로 대응해야 한다.

각 기능마다 MCP 도구를 만들면?
- 끝이 없다. 새 기능이 추가될 때마다 도구도 추가 -> 유지보수 불가능
- 뿐만 아니라 System Prompt Context 또한 증가한다. 채팅을 치지도 않았는데 MCP 자체만으로 Context 대부분이 찰 수가 있다.

기능마다 도구를 만드는 대신 더 좋은 방법
- 기능별 도구 방식의 한계: 도구 수가 기능 수에 비례해서 증가, 매번 새 도구의 스키마를 정의해야 함, 언리얼 업데이트 때마다 도구도 업데이트 필요
- 더 좋은 방법은 Claude가 코드를 통해서 언리얼 에디터를 컨트롤 해보자

도구 하나면 된다: execute_python
- 입력: Python 코드 문자열
- 실행: 에디터 안에서 직접 실행
- 출력: 실행 결과 반환
- 언리얼의 PythonScriptPlugin이 에디터 안에서 Python 코드를 실행해 줌
- Python으로 할 수 있는 것 = 에디터에서 할 수 있는 거의 모든 것
- 이게 가능한 이유는 Claude가 Unreal Python API를 이미 알고 있기 때문이다.
- 즉, 도구는 하나지만 Claude가 코드를 상황에 맞게 생성해서 무한한 기능을 커버할 수 있다

이 구조의 장점
- 도구 하나로 모든 기능 커버
- 새 기능 추가 = 코드 생성
- MCP 서버가 매우 단순
- 자동으로 발전

주의할 점
- 코드 직접 실행의 위험성: Python 코드를 에디터에서 직접 실행하므로, 잘못된 코드가 실행되면 프로젝트에 영향을 줄 수 있음
- 에러 처리와 결과 검증이 중요: 실행 결과를 반드시 검증하고, 에러 발생 시 안전하게 처리하는 로직이 필요
- 시스템 프롬프트로 안전장치 설정: Claude에게 "파일을 삭제하지 마라", "되돌릴 수 없는 작업 전에 확인해라" 등의 안전 지침을 줄 수 있음

핵심 정리
- PythonScriptPlugin이 실행 환경을 제공하고 Claude가 코드를 생성하고 MCP가 이 둘을 연결한다
- 도구 설계의 핵심: 기능을 하나씩 만들지 말고, 실행 환경을 도구로 만들어라
